# 아이폰 입금 정보 전달 — 한국어 설정 가이드

## 확인한 범위

2026-11-11 Apple 공식 문서는 이메일·메시지 수신 트리거와 `URL 콘텐츠 가져오기`의 JSON POST를 설명합니다. **토스 앱 푸시 본문을 단축어가 직접 읽는 경로는 이 작업에서 공식적으로 검증되지 않았습니다.** 기기/iOS 버전에 트리거가 보이더라도 본문이 전달되는지는 별도로 확인해야 합니다. 이 구현은 확실한 **수동 입력** 경로를 기본으로 제공합니다.

- [Apple 커뮤니케이션 트리거](https://support.apple.com/guide/shortcuts/communication-triggers-apdd711f9dff/ios)
- [Apple JSON POST 요청](https://support.apple.com/en-mt/guide/shortcuts/apd58d46713f/ios)

토스가 알림 원문 복사·공유를 제공하는지 확인되지 않았으므로, 가능하지 않으면 화면을 보고 필요한 값만 직접 입력합니다. 은행이 실제로 제공하고 본인이 신청한 SMS/이메일 알림이 있을 때만 해당 자동화 트리거를 검토하세요. 푸시 수신과 은행 입금 확정은 다릅니다.

## 준비

- 맥북 서버와 고정 HTTPS 도메인 구성 (`docs/cloudflare.md`). iPhone에서 localhost는 아이폰 자신이므로 사용하지 않습니다.
- `.env`의 **DEPOSIT_API_KEY만** 아이폰 단축어에 사용. ADMIN_API_KEY는 넣지 않습니다.
- 단축어에 인증키가 포함되므로 iCloud 공개 공유 링크를 만들지 않습니다.
- 토스 앱 알림을 보고 입금자명·실제 입금 시각·입금액을 확인합니다.

## 가장 확실한 수동 입력 단축어

단축어 앱에서 새 단축어 `입금 정보 전달` 생성. 표시명은 iOS 버전에 따라 조금 다를 수 있습니다.

1. **입력 요청**: 유형 텍스트, 질문 `입금자명`. 결과 변수 `입금자명`.
2. **입력 요청**: 유형 숫자, 질문 `입금액 (원, 쉼표 없이)`. 결과 `입금액`.
3. **입력 요청**: 유형 날짜 및 시간, 질문 `은행에 표시된 실제 입금 시각`. 결과 `입금시각`.
4. **날짜 포맷**: `입금시각`을 ISO 8601 또는 사용자 설정 `yyyy-MM-dd'T'HH:mm:ssXXX`. 결과 예: `2026-11-11T13:20:00+09:00`.
5. **알림 표시/결과 보기**로 이름·금액·시각을 표시. **메뉴에서 선택**으로 `전송` / `취소`를 구성하고 취소는 단축어 중단.
6. **사전** 생성 (아래 타입대로):

   | 키 | 유형 | 값 |
   |---|---|---|
   | depositor_name | 텍스트 | 입금자명 |
   | amount | 숫자 | 입금액 |
   | received_at | 텍스트 | 포맷된 입금시각 |
   | source | 텍스트 | shortcut_manual |
   | raw_notification | 텍스트 | 수동 입력 (또는 실제 확보한 최소 원문) |

7. 이 사전을 **텍스트로 변환**하고 **파일 저장**으로 `단축어/입금전송대기/`에 저장. 파일명은 `입금시각-입금자명.json`. 이 파일에는 인증키를 저장하지 않습니다. 민감 정보가 포함되므로 기기 잠금·iCloud 동기화 범위를 확인합니다.
8. **URL**: `https://store.YOUR-DOMAIN/api/deposits`.
9. **URL 콘텐츠 가져오기** → 메서드 `POST` → 헤더 `X-API-Key`에 로컬 키, `Content-Type`에 `application/json` → 요청 본문 `JSON` → 6번 표의 키·값·유형을 각각 추가합니다. 텍스트 JSON 문자열을 JSON 필드 하나에 넣지 않습니다.
10. **결과 보기**. 성공 응답에는 `id`, `verification_status`가 있습니다. `MATCHED_UNVERIFIED`도 입금 확정이 아닙니다.
11. 응답의 `id`가 있을 때만 해당 대기 파일을 확인 후 삭제하거나 완료 폴더로 이동합니다. 네트워크 실패는 동작 자체를 중단할 수 있으므로, 전송 전에 파일을 보관하는 것이 중요합니다.

## 원문에서 추출하는 선택 경로

알림 본문을 실제로 복사/공유할 수 있을 때만 입력으로 받습니다. 공유 시트에서 텍스트 받기를 켜고 입력이 없으면 `입력 요청`으로 대체합니다. **토스 원문 형식을 임의로 가정하지 않습니다.**

이 시스템에서 제공하는 명시적 수동 표준 형식:

```text
입금: 김철수: 3,000원
```

**텍스트 일치** (정규식):

```regex
입금\s*[:：]\s*([^\n:：]+?)\s*[:：]\s*((?:\d{1,3}(?:,\d{3})+|\d+))\s*원
```

일치 그룹 1은 입금자명, 그룹 2는 금액. 그룹 2의 `,`를 빈 문자열로 바꾸고 숫자로 변환합니다. 이름 앞뒤 공백을 제거합니다. 일치가 없거나 여러 개면 자동 선택하지 말고 수동 입력합니다. 결과를 사용자에게 보여 확인 후 전송합니다. 실제 토스 알림 예시를 확보한 뒤에만 별도 정규식을 추가하고 출금·잔액·복수 금액 문구를 음성 테스트하세요. 서버는 NFKC·공백 제거·대소문자 정규화를 추가 적용합니다.

서버의 `POST /api/deposits/parse`도 이 표준 형식만 파싱하며 `requires_confirmation=true`를 반환합니다.

## 재전송 단축어

1. 파일 선택 → 위 대기 폴더의 JSON 선택.
2. 입력에서 사전 가져오기 → 기존 필드를 꺼내 동일 JSON으로 POST.
3. **received_at을 현재 시각으로 바꾸지 않습니다.** 이름·금액·시각·source가 동일하면 같은 이벤트로 처리됩니다. 원문만 달라져도 중복 방지는 유지됩니다.
4. 응답 `id` 확인. 200은 기존 이벤트, 201은 새 이벤트, 401은 키 확인, 422는 타입/시간대/본문 확인, 429는 대기 후 같은 본문 재시도.

동일한 실거래를 서로 다른 시각·source로 반복 입력하면 별도 이벤트가 될 수 있습니다. 관리자 대시보드에서 같은 이름·금액·근접 시각을 반드시 비교하세요. 알림에는 은행 고유 거래 ID가 없어 완전한 실거래 중복 판별이 불가능합니다.

